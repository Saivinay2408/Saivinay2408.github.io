How it works

🛡️ Aegis — AI Operating System Layer

Your OS, supercharged with AI. Aegis is a JARVIS-like AI assistant that deeply integrates with macOS, powered by GitHub Copilot (free with GitHub account) with 64K–128K context windows.

✨ What Makes Aegis Different

Most AI assistants are chatbots. Aegis is an OS layer — it sees your system, controls your apps, runs commands, manages files, and talks to you in real-time voice. Every action goes through a built-in security supervisor so nothing dangerous happens without your approval.

🛡️ The Guardian — Built-in Security

Every single action Aegis takes passes through an AI security supervisor:

You → Doer AI → 🛡️ Guardian AI → Execute (or Block)
Risk Level Example Behavior
🟢 Safe Read a file Auto-approved
🟡 Low Create a file Auto-approved + logged
🟠 Medium Install a package Asks you first
🔴 High Delete files Requires confirmation + snapshot
⛔ Forbidden rm -rf / Hard blocked, no override possible

🎤 Voice Control

/voice on       # Start voice mode
/voice off      # Stop
/voice status   # Check status

Voice pipeline: - Wake word → Alexa-compatible local detection (no cloud) - STT → OpenAI Whisper (base.en, runs locally, very fast) - TTS → macOS native say command (instant, no API) - Barge-in → Speak to interrupt when using headphones, Enter key on speakers

Note on barge-in: This is a fundamentally hard problem. When using built-in speakers, the mic picks up the TTS audio at full Silero VAD confidence (prob=1.00 — proven by logging). Hardware AEC is required for reliable mic-based barge-in, which is what ChatGPT/Siri use at the OS level. With headphones/AirPods, barge-in works perfectly via Silero VAD since the mic is isolated.

⚙️ Configuration

# ~/.aegis/config.yaml
llm:
  provider: auto       # auto → tries copilot first
  model: gpt-4o

guardian:
  enabled: true
  auto_approve_safe: true
  auto_approve_low_risk: true

voice:
  enabled: false
  stt_model: base.en   # tiny.en / base.en / small.en
  wake_word: alexa

enabled_agents:
  - system
  - file
  - shell
  - web
  - app
  - automation

🔐 How GitHub Copilot Auth Works

Aegis uses the same OAuth device flow as VS Code:

  1. Client ID Iv1.b507a08c87ecfe98 (VS Code Copilot Chat)
  2. Device code → user authorizes at github.com/login/device
  3. Token saved to ~/.aegis/copilot_token.json (mode 600)
  4. Per-request: token exchanged via copilot_internal/v2/token
  5. Requests sent to api.individual.githubcopilot.com

Requirements: GitHub account + Copilot access (Free tier included for individuals).
